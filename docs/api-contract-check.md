## Backend changes needed

- Password reset emails currently include only a signed `uid`, while confirmation requires both `uid` and `token`; the `token` field is not validated or used. Frontend now sends the signed uid as both fields to satisfy the serializer. Prefer removing the redundant token requirement (or issue and validate a distinct token) in the backend.
- Registration returns only a detail message after sending email verification, so the frontend cannot establish an authenticated session until login. The frontend now reflects that behavior.
- The generated OpenAPI schema omits request/response detail for several `APIView`s (including auth, alert preferences/unsubscribe, and review summary/helpful operations) because schema introspection cannot infer serializers. Route/method checks cover operations present in the snapshot; payload tests and backend serializer/view inspection cover these omitted details.
- Reviews are implemented in the backend but the frontend has no review service or active review UI. Implementing review presentation/submission is additional frontend feature work, not a wire mismatch in an existing client.
